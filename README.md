# 个人近况

以文字为主的个人近况页，包含历史记录、习惯热图、阅读卡片与关联图。首批阅读内容为 8 张已确认公开的读后感，不包含书籍原文。代码、公开数据、字体与插画由 GitHub 保存，Vercel 运行页面和管理接口。

## 本地运行

使用 Node.js 22。没有第三方运行依赖。

- npm test：运行内容边界、身份、存储、路由和构建测试。
- npm run build：校验公开内容并构建到 dist。
- npm run check：检查输入、产物白名单和敏感信息模式。
- npm run dev：启动本地预览，不提供假登录或身份绕过。

本地测试使用模拟 GitHub 服务，不能替代正式部署后的登录与写入验收。

## 公开内容

- content/public-site.json：经核实的近况、历史与习惯数据。未知时长和完成状态为 null，不按 0 或 false 处理。
- content/reading-library.json：已选择的公开阅读卡片、书目与主题。分页绑定快照版本。
- config/public-files.json：静态发布白名单；管理页 HTML 不进入静态公开产物。

服务器拒绝未知字段、错误类型和常见敏感信息模式。自动扫描不能取代人工隐私及版权核验。不要提交私人记录、原始聊天、书籍全文或未经批准的书摘。

## 登录与更新

管理页及写接口在服务器验证指定 GitHub 数字账号 ID。登录 OAuth 仅请求 read:user；会话使用签名、Secure、HttpOnly cookie。写请求还需同源校验和当前内容版本，避免覆盖并发修改。

配置项见 .env.example。真实密钥只存入部署平台的安全环境变量，不写入仓库、前端、日志或聊天。内容写凭据应仅允许此仓库的 Contents 读写；GitHub 不能把它限制到单个文件，服务器额外固定 content/public-site.json 路径。

对话更新可通过已授权的 GitHub 连接完成：读取最新文件和 blob SHA，检查公开范围，提交合规 DTO，然后核对网页。此路径无需站内聊天机器人。公开内容跨实例缓存最长约 30 秒；后台读取和写入不缓存。仅近况内容变更不触发代码重建，阅读库与代码变更需要重新构建。

## 部署与验收

Vercel 配置使用 npm run build、dist 输出目录与 Node.js 22。vercel.json 定义 API 路由、安全响应头和构建忽略规则。

部署前需确认仓库、公开内容及必要的账号权限。专用 OAuth 应用、仓库写凭据和持久权限应分别通过正式流程批准配置。登录 callback 必须是实际站点的 APP_ORIGIN/api/auth/callback。

首次上线后应验证公开页面、本人登录、非本人拒绝、匿名写入拒绝、版本冲突、真实内容更新及回滚。不要把模拟测试通过写成生产验收完成。

## 回滚

后台可将最近 30 个近况内容版本恢复成新提交，不删除历史或改写代码。代码可用 Git revert 或已核实的 Vercel 历史部署恢复。不要 force-push 删除历史；删除公开文件也不能清除第三方缓存。

字体使用霞鹜文楷，许可证保留在 public/assets/fonts/OFL.txt。
